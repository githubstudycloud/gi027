# 99 - 方案对比与决策矩阵

> 仅记录关键技术选型的横向对比与最终结论，便于事后复盘。
> 评分维度：S（生态）/ M（维护性）/ I（与 SB4 集成）/ C（学习成本）/ R（风险），1~5 分，分值越高越好（R 反向）。

---

## 1. 接口文档生成

| 候选 | S | M | I | C | R | 结论 |
|------|---|---|---|---|---|------|
| **springdoc-openapi 2.6** | 5 | 5 | 5 | 4 | 1 | ✅ 选用，Spring Boot 4.x 官方推荐 |
| Springfox | 3 | 1 | 1 | 4 | 5 | ❌ 已停更，不兼容 Jakarta |
| 手写 OpenAPI + 不用注解 | 4 | 3 | 3 | 2 | 3 | ❌ 协作成本高 |

## 2. Mock Server

| 候选 | 用途 | 结论 |
|------|------|------|
| **Prism** | 契约 Mock（M1） | ✅ 选用，与 OpenAPI 直接对应 |
| **WireMock** | 录制/状态/故障（M2~M4） | ✅ 选用 |
| MockServer | 同 WireMock | ❌ 备选，生态略弱 |
| Hoverfly | 录制回放 | ❌ 仅备份 |

## 3. 契约测试

| 候选 | 模式 | 结论 |
|------|------|------|
| **Schemathesis** | 提供方 + 模糊 | ✅ 默认 |
| **Pact** | 消费者驱动（CDC） | ✅ 跨服务首选 |
| Spring Cloud Contract | 双向 | 备选（仅纯 JVM 团队） |
| Dredd | 提供方 | ❌ 维护慢 |

## 4. 集成测试基础设施

| 候选 | 结论 |
|------|------|
| **Testcontainers + `@ServiceConnection`** | ✅ 唯一选项 |
| H2 / 嵌入式 Redis / EmbeddedKafka | ❌ 强禁 |

## 5. E2E

| 候选 | 表达力 | 团队成本 | 结论 |
|------|--------|---------|------|
| **Karate** | 高 | 低 | ✅ 默认 |
| Postman + Newman | 中 | 低 | 仅辅助导出 |
| RestAssured | 高 | 高 | 已在 L3 使用，不重复 |
| Playwright API | 高 | 中 | 备选（前端共用） |

## 6. 日志框架与结构化

| 候选 | 结论 |
|------|------|
| **Logback + Logstash encoder + 公司 logging-starter** | ✅ |
| Log4j2 + JSON layout | 备选（性能优先项目） |
| 文本日志 + 后端解析 | ❌ 禁止 |

## 7. 链路追踪

| 候选 | 结论 |
|------|------|
| **OpenTelemetry（Java agent + SDK）** | ✅ |
| Sleuth | ❌ Spring 已合并到 Micrometer Tracing |
| 自研拦截器 | ❌ |

## 8. 流水线

| 候选 | 结论 |
|------|------|
| **GitHub Actions**（外部） / **GitLab CI**（内网） | ✅ 二选一，按现有基建 |
| Jenkins | 仅遗留维持 |

## 9. 需求载体

| 候选 | 优势 | 劣势 | 结论 |
|------|------|------|------|
| **Markdown in Git（PRD-as-Code）** | 与代码同 PR、可 diff、可追溯 | 协作弱于 Jira | ✅ 选用，搭配脚本回填覆盖 |
| Jira / 飞书多维 | 协作强 | 与代码割裂 | 仅做需求池/路线图 |

## 10. 测试数据

| 候选 | 结论 |
|------|------|
| **YAML Fixture + Builder DSL（双轨）** | ✅ |
| 仅 SQL dump | ❌ 不易演化 |
| 全程 Faker | ❌ 不可复现 |

---

## 11. 总体决策（一页纸）

| 主题 | 选型 |
|------|------|
| 单一事实源 | OpenAPI 3.1 + AsyncAPI 3.0 入仓 |
| 文档 | springdoc 2.6 + Redoc 发布 |
| 契约门禁 | Spectral + openapi-diff + annotation-vs-spec |
| Mock | Prism + WireMock + Toxiproxy |
| 测试分层 | JUnit5 + WebTestClient + Testcontainers + Schemathesis + Pact + Karate |
| 数据 | Flyway Seed + YAML Fixture + Builder DSL |
| 日志 | JSON + OpenTelemetry + 错误聚类 |
| 流水线 | GH Actions / GitLab CI（13 阶段） |
| 看板 | Allure + Grafana + Backstage（可选） |
| 需求 | PRD-as-Code（Markdown in Git）+ AC 编号永不复用 |

---

## 12. 已知不做（Out of Scope）

- 不引入商业 ALM（TestRail / Zephyr 等）
- 不做"全链路录制回放生产流量"（成本与合规过高）
- 不做"用例 AI 自动生成"主路径（仅作辅助建议）
- 不替换团队已有 IM 告警通道（仅做适配器接入）
