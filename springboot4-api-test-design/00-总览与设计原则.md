## 2. 设计目标（What success looks like）

1. **单一事实源**：所有接口契约（内部 / 外部）以 OpenAPI / AsyncAPI 形式入库，文档、Mock、用例、SDK 全部由此派生。
2. **需求即用例**：每条 PRD 验收标准（AC）必须能反查到至少一条自动化用例与一段日志关键字。
3. **连通可视化**：任意时刻能在一张图上回答"我依赖谁、谁依赖我、当前是否连通、平均时延"。
4. **数据可预填、可重置**：任何环境（local / test / beta）能在 5 分钟内回到一组确定性的测试基线数据。
5. **左移发现**：>= 70% 的问题在 **CI 阶段** 暴露；剩余在 **预发** 通过日志 / 链路特征自动告警，而非等用户反馈。
6. **可回滚的契约变更**：API 变更 = 契约变更 = 流水线事件；破坏性变更必须经契约门禁。

## 3. 术语统一

| 术语 | 含义 |
|------|------|
| **内部接口 (Internal API)** | 同企业 / 同信任域内由本团队或兄弟团队提供的接口（含本服务自身 HTTP / RPC / MQ 入口） |
| **外部接口 (External API)** | 跨信任域的三方接口（支付、短信、身份、AI 平台等） |
| **契约 (Contract)** | 描述接口形状的机器可读文件：OpenAPI / AsyncAPI / Proto |
| **连通 (Reachability)** | 三层语义：网络可达 → 协议可达 → 业务可达（探针响应符合契约） |
| **AC (Acceptance Criteria)** | 需求验收标准，Gherkin 风格，与用例 1:N |
| **Fixture** | 一组确定性的测试输入数据 + 期望输出 |
| **预填 (Seeding)** | 启动或用例前自动写入 Fixture 的过程 |
| **影子调用 (Shadow Call)** | 生产/预发流量复制到测试环境，仅用于诊断不影响线上 |

## 4. 横切原则（强制）

### 4.1 契约先行（Design-First）
- 任何新接口：**先评审 OpenAPI 片段，再写代码**。
- Controller 注解用于"补充"契约（示例、错误码），不得反向定义契约结构。
- 契约文件入仓路径：`docs/api/openapi/<服务名>-<版本>.yaml`。

### 4.2 测试金字塔（强制比例）

| 层级 | 比例参考 | 是否阻塞合并 |
|------|---------|-------------|
| L1 单元 | 60% | ✅ 阻塞 |
| L2 切片（WebMvc / DataJpa） | 20% | ✅ 阻塞 |
| L3 集成（Testcontainers） | 12% | ✅ 阻塞 |
| L4 契约（CDC / Pact / SCC） | 5% | ✅ 阻塞（仅契约变更时） |
| L5 E2E / 烟雾 | 3% | ⚠️ 部署后阻塞晋级 |

### 4.3 三禁

1. **禁止裸 IO 直连外部接口**：所有外部调用必须经 `*-integration` 模块的 Adapter，方便统一注入超时 / 重试 / 录制 / Mock。
2. **禁止用例硬编码"魔法数据"**：必须通过 Fixture / DataFactory 产生，保证可重放。
3. **禁止吞日志**：异常必须带 `traceId + 业务键 + 失败上下文`，否则 CI 拒绝（见 07）。

### 4.4 三必

1. **每个接口必须有 ≥ 1 条 happy path + ≥ 1 条契约边界用例**。
2. **每个外部接口必须有 ≥ 1 套 WireMock 录制 + 1 套故障场景**（超时 / 5xx / 限流 / 数据不合规）。
3. **每次接口变更必须产出"差异说明 + 影响面用例 + 文档更新"三件套**，由流水线检查。
