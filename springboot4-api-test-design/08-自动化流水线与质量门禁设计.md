# 08 - 自动化流水线与质量门禁设计

> 目标：让"需求 / 文档 / 测试 / 日志"四件事在每次提交都被自动检查、可视化、可阻塞。

---

## 1. 流水线总体阶段

```
┌─────────┐ ┌──────────┐ ┌──────────┐ ┌──────────┐ ┌──────────┐ ┌──────────┐
│  Lint   │►│  Build   │►│ Unit/L1  │►│ Slice/L2 │►│  IT/L3   │►│ Contract │
└─────────┘ └──────────┘ └──────────┘ └──────────┘ └──────────┘ └──────────┘
                                                                       │
┌──────────┐ ┌──────────┐ ┌──────────┐ ┌──────────┐ ┌──────────┐       │
│ DocsBuild│◄│ Coverage │◄│ Spectral │◄│OpenAPI-  │◄│ Annot-vs-│◄──────┘
└──────────┘ └──────────┘ └──────────┘ │   diff   │ │   spec   │
     │                                 └──────────┘ └──────────┘
     ▼
┌──────────┐ ┌──────────┐ ┌──────────┐ ┌──────────┐
│ Publish  │►│  Deploy  │►│ Smoke/L5 │►│  Probe   │
└──────────┘ └──────────┘ └──────────┘ └──────────┘
```

> 单 PR 阶段（前 8 个）目标 ≤ 10 分钟；夜间扩展跑混沌 / 性能 / 大型 E2E。

---

## 2. 每阶段的产物与门禁

| 阶段 | 产物 | 阻塞规则 |
|------|------|---------|
| Lint | checkstyle / pmd 报告 | 错误 = 阻塞 |
| Build | jar / sbom | 失败 = 阻塞 |
| L1 单元 | junit + coverage | 行覆盖 < 阈值（见 §3）阻塞 |
| L2 切片 | junit | 失败阻塞 |
| L3 集成 | junit + Testcontainers 日志 | 失败阻塞；时长 > 5min 警告 |
| L4 契约 | pact / schemathesis | 失败阻塞（仅契约改动 PR） |
| Spectral | lint 报告 | 错误阻塞 |
| OpenAPI-diff | break / non-break 标签 | break 必须勾选"已通知消费者" |
| Annotation-vs-spec | drift 报告 | drift 阻塞 |
| Coverage | 聚合报告 | 见 §3 |
| DocsBuild | Redoc 静态站 | 渲染失败阻塞 |
| Publish | docker / sdk / docs | 失败阻塞 |
| Deploy | env diff | 配置 diff 必须人工确认（见 [arch-design/04](../springboot4-arch-design/04-配置中心与灰度发布设计.md)） |
| Smoke L5 | karate 报告 | 失败 = 自动回滚 |
| Probe | 连通矩阵 diff | 新增红格 = 回滚候选 |

---

## 3. 质量门禁（最小集合）

| 维度 | 阈值 | 说明 |
|------|------|------|
| 行覆盖（service/usecase 包） | ≥ 80% | 业务层 |
| 行覆盖（controller / mapper） | ≥ 60% | 边界层 |
| 分支覆盖 | ≥ 70% | 核心域强制 |
| 圈复杂度 | ≤ 4（与 arch-design 一致） | Checkstyle |
| AC 自动化覆盖（P0） | 100% | 见 01 |
| 接口在 catalog | 100% 入册 | 见 02 |
| 契约 lint | 0 error | Spectral |
| 契约 break change | 必须显式确认 | openapi-diff |
| 录制过期 | 0 录制 > 12 月 | 见 06 |
| 日志 schema | 0 缺必填字段 | log-lint |
| Flaky 用例率 | < 1% | 重跑统计 |

## 4. 报告聚合与可视化

| 看板 | 来源 | 形式 |
|------|------|------|
| 测试报告 | Allure | 按 `@Tag(REQ-...)` 聚合 |
| 覆盖率 | Jacoco aggregate | 模块矩阵 |
| 契约状态 | Spectral + diff | API 健康看板 |
| 连通矩阵 | 探针指标 | Grafana |
| 错误模式 | 日志聚合 | "今日错误地图" |
| 需求覆盖 | 01 章脚本 | PRD 根目录页 |

> 一个 PR 评论里贴 6 个看板链接（机器人自动评论）。

---

## 5. 工件与可追溯（PR 维度）

每次 PR 在 GitHub Action artifact 中归档：
- `test-results/` JUnit XML
- `coverage/` Jacoco
- `openapi/<service>-<sha>.yaml`（即变更后的契约）
- `openapi-diff.html`
- `requirement-coverage.json`
- `connectivity-matrix-before-after.diff`
- `failure-bundle/`（任意失败用例的 fixture + seed + wiremock recording id + traceId）

> 任何线上故障 30 天内可凭 commit sha 重放整套上下文。

---

## 6. 分支策略与流水线

| 分支 | 触发 | 跑哪些阶段 |
|------|------|-----------|
| feature/* PR → main | push / PR | Lint → L1 → L2 → L3 → 契约 → 文档 |
| main | merge | 全量 + Publish + Deploy(test) |
| release/* | push | 全量 + Deploy(beta) + Smoke + Probe |
| nightly cron | 02:00 | + 契约消费者校验 + 性能 + 混沌 |
| hotfix/* | push | 同 PR + 强制 P0 全过 |

---

## 7. Flaky 治理

- 单测连续 3 次 fail → "稳定失败"
- 1 fail 1 pass 交替 → 标记 `@Tag("flaky")`，进入隔离队列
- 隔离队列每周 review；超过 2 周未修 → 升级 P1 工单
- 任何 PR 不允许新增 flaky（CI 比对）

---

## 8. 演练与灾备

- 月度：随机回滚一次"上一发布版本"，检验回退能力
- 季度：snapshot 恢复演练（见 05）+ 三方录制刷新（见 06）
- 半年：跨服务契约不兼容演练（消费者用旧版 SDK 撞当前服务，验证 sunset 策略）
