# 07 - 日志与早期问题发现设计

> 目标：在用户告诉我们之前发现问题。
> 手段：**结构化日志 + 链路 traceId + 契约偏离探测 + 错误模式聚合 + 健康冒烟**。

---

## 1. 日志的三类用途（不要混）

| 类别 | 用途 | 受众 | 保留期 |
|------|------|------|-------|
| **业务日志（business）** | 流程关键节点，可追溯需求 | 业务/产研 | 90 天 |
| **诊断日志（diagnostic）** | 报错上下文、慢调用、契约偏离 | 研发/SRE | 30 天 |
| **审计日志（audit）** | 安全/合规 | 安全/审计 | ≥ 1 年 |

> 同一行日志只承担一种用途；混用是混乱之源。

---

## 2. 结构化日志强约束

- 格式：JSON，统一 schema：
```json
{
  "ts": "2026-04-28T10:11:12.345+08:00",
  "level": "WARN",
  "service": "user-service",
  "logger": "c.x.user.LoginService",
  "msg": "账号锁定",
  "traceId": "ab12cd34...",
  "spanId": "ef56...",
  "userId": "u_***1",                  // 已脱敏
  "req": "REQ-2026-001-AC-02",         // 见 01 章
  "api": "POST /v1/auth/login",
  "extKeys": { "attempts": 5, "lockedFor": 900 },
  "errCode": "USER_LOCKED",
  "exception": null
}
```

- **必带字段**（缺失 = CI lint 警告）：`ts, level, service, logger, msg, traceId`
- **WARN/ERROR 必带**：`errCode` + `extKeys`（业务上下文键值）
- **PII 字段**：必须经 §05 masker，明文写入 = 静态扫描阻断
- **禁止**：拼接字符串日志（`log.info("user " + id)`），统一占位符 + 上下文 map。

---

## 3. 链路 (traceId) 全栈贯穿

- 入口：HTTP / MQ / 定时任务统一注入 traceId（OpenTelemetry）。
- 出口：所有外部调用（Adapter）必须把 traceId 写入：
  - HTTP header（W3C TraceContext）
  - MQ 消息头
  - SQL 注释（`/* traceId=... */ select ...`）便于 DB 慢日志关联
- 异步切换：`@Async` / `CompletableFuture` 必须用统一的 `TraceablePropagator`。
- 用例侧：**测试用例日志也带 traceId**，CI 失败日志可直接喂回放。

---

## 4. 早期发现的"四只眼"

### 4.1 第一只眼：契约偏离探测器（Contract Drift Detector）
- 在 Adapter 层（出站）+ Filter 层（入站）抽样校验响应/请求是否符合契约 schema。
- 偏离 → WARN + 指标 `contract_drift_total{api,direction}`。
- 阈值：5 分钟偏离率 > 1% → 告警。
- **价值**：在用户复现 bug 之前，先报"上游接口悄悄改了字段"。

### 4.2 第二只眼：慢调用与超时预警
- 每个 outbound 接口在 02 章声明了 `sla.p95_ms`，运行期对比：
  - `actual_p95 > sla.p95_ms × 1.5` → WARN
  - `actual_p95 > timeout × 0.8` → ERROR（即将超时）
- 直接关联到连通矩阵中的 P95 列。

### 4.3 第三只眼：错误模式聚合（Error Pattern Mining）
- 所有 ERROR 日志按 `(service, errCode, api)` 聚类。
- 日聚合 Top-N → 自动生成"今日错误地图"（@Daily 报告）。
- 突增（同比 > 200%）→ 自动建 Issue 并 @owner（来自 02 章 owners）。

### 4.4 第四只眼：连续冒烟（Always-On Smoke）
- §02 探针 30s 一次跑 L3 烟雾用例。
- 烟雾失败连续 ≥ 2 次 → 触发"问题分诊机器人"：
  - 自动拉取最近 5 分钟错误日志、契约 drift 事件、部署事件
  - 在 IM 群发出"嫌疑人列表"

## 5. 关键日志埋点清单（强制）

| 位置 | 必埋字段 | 用途 |
|------|---------|------|
| Controller 入口 | api, traceId, userId | 入站审计 + 漏斗 |
| Service 编排关键节点 | step, businessKey | 漏斗失败定位 |
| Adapter 出站前后 | vendor, api, latency, status | 契约偏离 / 慢调用 |
| 重试 / 熔断切换 | from, to, reason | 故障演化轨迹 |
| 异常兜底 | errCode, cause class, stack-hash | 聚合去重 |
| MQ 生产/消费 | topic, partition, offset, traceId | 端到端链路 |
| 定时任务 | jobId, runId, durationMs | 静默失败发现 |

> "stack-hash" = 异常堆栈前 N 行的哈希，用于错误模式聚合，不打全栈到生产。

---

## 6. 与测试的双向反哺

- **测试 → 日志**：用例 fail 时把 fixture / seed / wiremock-recording 写进失败日志（见 05 §7）。
- **日志 → 测试**：生产/预发出现的新错误模式 → 自动生成"未覆盖用例工单"，关联到 §01 的 AC：
  - 如果该错误模式无对应 AC → 触发"需求漏写"评审
  - 如果有 AC 但无用例 → 触发"测试漏写"

---

## 7. SLO（早期发现指标）

| 指标 | 目标 | 计算 |
|------|------|------|
| MTTD（平均发现时间） | < 5 分钟 | 第一条用户反馈 vs 系统首条告警 |
| 告警有效率 | ≥ 80% | 真问题 / 总告警 |
| 契约偏离捕获率 | ≥ 95% | drift detector 命中 / 实际偏离 |
| 用例可复现率 | 100% | 仅靠日志键能否本地复现 |

---

## 8. 反模式（红线）

1. ❌ `log.error("失败", e)` 不带 errCode / 上下文
2. ❌ 把 `Exception.printStackTrace()` 写到任何日志通道
3. ❌ 在 INFO 级输出全量请求体 / 响应体（性能 + PII 双爆雷）
4. ❌ 用 `System.out / println` 调试代码进生产
5. ❌ 同一异常在多层重复打印（必须"捕获即转换或抛出"，禁止"打印再抛")

---

## 9. 评审清单

- [ ] JSON 日志 schema 是否一刀切（含老服务）
- [ ] 契约偏离探测器是否默认开启（性能损耗预算）
- [ ] MTTD < 5min 是否有运维支撑
- [ ] 错误聚类的 stack-hash 算法（前 N 行 N=?）
