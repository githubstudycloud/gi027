# 03 - 接口契约与文档自动化设计

> 核心信条：**OpenAPI / AsyncAPI 是单一事实源**。文档、Mock、SDK、用例骨架、连通探针全部由它派生，禁止"代码改了文档没改"。

---

## 1. 契约的形态与版本

| 接口类型 | 契约格式 | 路径约定 |
|---------|---------|---------|
| HTTP/REST | OpenAPI 3.1 | `docs/api/openapi/<service>-v<major>.yaml` |
| 异步事件 | AsyncAPI 3.0 | `docs/api/asyncapi/<service>-events-v<major>.yaml` |
| gRPC | `.proto` | `docs/api/proto/<service>/v<major>/*.proto` |
| 外部三方 | OpenAPI / 抓包导出 | `docs/api/contracts/external/<vendor>-<api>-<日期>.yaml` |

版本规则：
- **MAJOR**：破坏性变更（删字段、改类型、改语义）
- **MINOR**：兼容新增
- **PATCH**：纯文档 / 示例 / 描述
- 破坏性变更 → 流水线门禁（详见 §5），必须新建 v2 路径并保留 v1 至少 2 个迭代。

---

## 2. Design-First 工作流

```
1. 撰写/修改 OpenAPI 片段（PR 提交）
2. 评审：API Reviewer + Owner
3. CI 通过：lint + diff + 兼容性检查
4. 合并后自动产出：
   - 静态文档站点 (Redoc / Stoplight)
   - Mock Server 镜像 (Prism / WireMock)
   - 服务端骨架（可选，openapi-generator → 仅生成接口与 DTO）
   - 客户端 SDK（其他团队/前端使用）
   - 用例骨架（每 operation × {happy, 4xx, 5xx, schema-边界}）
5. 业务代码实现接口；CI 验证实现 vs 契约一致性
```

代码内只用注解**补充**契约（示例值、错误码描述），不得**新建**字段：

```java
@Operation(operationId = "loginByPassword", summary = "账号密码登录")
@ApiResponse(responseCode = "423",
  description = "账号已锁定", content = @Content(schema = @Schema(ref = "#/components/schemas/Error")))
public ResponseEntity<TokenVO> login(@RequestBody @Valid LoginCmd cmd) { ... }
```

> 检查工具：`openapi-diff`（结构差异）+ 自研 `annotation-vs-spec`（注解新增字段未在契约中）。

## 3. 工具链选型（Spring Boot 4.x 兼容）

| 能力 | 选型 | 备注 |
|------|------|------|
| 服务端文档生成 | **springdoc-openapi 2.6+** | Springfox 已停更，禁用 |
| 静态站点 | **Redoc** + GitHub Pages | 单页好阅读，CI 发布 |
| 多服务聚合门户 | Backstage / Stoplight Elements | 大型组织可选 |
| Mock Server | **Prism**（契约 mock） + **WireMock**（脚本 mock） | 详见 06 |
| 契约 lint | **Spectral**（自定义规则集） | 强制命名 / 错误模型 / 安全字段 |
| 兼容性 diff | **openapi-diff** + 自定义破坏规则 | 阻塞 break change |
| 客户端 SDK | **openapi-generator**（java/ts/python） | 月度统一发版 |
| 异步契约 | **AsyncAPI Generator** | 生成 Kafka producer/consumer 骨架 |

## 4. Spectral 规则集（关键约束）

落地 `tools/spectral/ruleset.yaml`：

- **命名**：路径 kebab-case；字段 lowerCamelCase；操作 ID = `<resource><Action>`。
- **必填**：每个 4xx / 5xx 响应 schema 必须 `$ref: '#/components/schemas/Error'`。
- **安全**：禁止在 query 中传递 token；登录类接口必须声明 `security`。
- **示例**：每个 schema 必须有 `example`（用于 Mock 与文档）。
- **追溯**：每个 operation 必须有 `x-owners` 与（业务接口）`x-requirements`。
- **分类**：必须有 `x-classification.criticality` ∈ {P0,P1,P2}。

> 规则集由 platform-team 维护，业务团队仅可"加"不可"减"。

## 5. 契约门禁（强制流水线步骤）

```
┌──────────────┐   ┌──────────────┐   ┌──────────────┐   ┌──────────────┐
│ Spectral lint│──►│ openapi-diff │──►│ annotation-vs-spec │──►│ 契约用例运行 │
└──────────────┘   └──────────────┘   └──────────────┘   └──────────────┘
       ↓ fail              ↓ break              ↓ drift              ↓ fail
     阻塞 PR             阻塞 PR              阻塞 PR             阻塞 PR
```

- **break change** 解锁条件：PR 描述里勾选"我已通知所有消费者 + 已新建 v2"。
- **drift（注解 vs 契约不一致）**：必须二选一同步。

## 6. 文档发布

每次合入 main：
1. 渲染 Redoc 静态文件 → `gh-pages` 分支 → 公司 API Portal 拉取。
2. 推送 `catalog.yaml` 给 Backstage/门户聚合。
3. 推送 OpenAPI 到内部 Mock Server，刷新 Mock 路由。
4. SDK 月度发版（聚合若干 minor 版本）。

文档站结构：
```
api-portal/
  ├─ user-service/
  │   ├─ v1 (current)
  │   └─ v0 (deprecated, sunset: 2026-09-01)
  ├─ order-service/
  └─ external/
      └─ aliyun-dysms/
```

## 7. 异步事件契约（AsyncAPI）

- 每个 Topic 对应一个 schema 版本目录：`schemas/<topic>/v<n>.json`
- 生产者必须声明 `traceId / occurredAt / partitionKey` 三个公共字段
- 消费者必须支持 **schema 兼容回退**（旧版本可解析 = ok）
- 破坏性事件变更 = 新建 `topic.v2`，老 topic 双写 1 个迭代后下线

---

## 8. 风险与对策

| 风险 | 对策 |
|------|------|
| 注解漂移（代码改了忘改契约） | annotation-vs-spec 阻塞合并 |
| 契约过度设计 | Spectral 规则只罚"必要"，不强求 RFC 完美 |
| 多语言 SDK 维护成本 | 月度统一发版 + 仅 java/ts 强保 |
| 外部三方契约缺失 | 06 章节"录制即契约"模式 |
