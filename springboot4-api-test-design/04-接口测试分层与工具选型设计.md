# 04 - 接口测试分层与工具选型设计

> 目标：用最少、最稳定的工具组合覆盖全部测试层级，避免"工具节"。
> 每一层定义清晰：**输入边界、隔离边界、断言边界、跑在哪、何时跑**。

---

## 1. 测试金字塔（强制比例）

| 层 | 名称 | 输入边界 | 隔离边界 | 工具 | 跑在哪 | 阻塞合并 |
|---|------|---------|---------|------|--------|---------|
| L1 | 单元 | 类方法 | 全 mock | JUnit 5 + Mockito | 本地 / CI | ✅ |
| L2 | 切片 | Web/数据切片 | 容器外 | `@WebMvcTest` / `@DataJpaTest` / **WebTestClient** | 本地 / CI | ✅ |
| L3 | 集成 | 进程 + 真实中间件 | 容器内 | **Testcontainers** + RestAssured / WebTestClient | CI | ✅ |
| L4 | 契约 | 实现 vs 契约 | 双向 | **Spring Cloud Contract** 或 **Pact** + Schemathesis | CI（契约改动时） | ✅ |
| L5 | E2E / 烟雾 | 多服务部署后 | 真实环境 | **Karate** / Newman / Playwright API | 部署后 | 晋级阻塞 |
| L6 | 探索 / 混沌 | 黑盒 | 真实环境 | Chaos Mesh / Toxiproxy + Schemathesis | 周期 / 演练 | ❌ |

---

## 2. 各层职责切分（避免重叠）

| 关注点 | 应在哪一层 | 不应在哪一层 |
|-------|-----------|-------------|
| 业务规则正确性 | L1 / L2 | L3+ |
| 序列化/反序列化、参数校验 | L2 | L1（mock 易遗漏） |
| 持久化 SQL / 索引 / 事务 | L3 | L2（H2 不真实） |
| 缓存命中、幂等键 | L3 | L1 |
| 鉴权 / 网关链路 | L3（带网关镜像） / L5 | L2 |
| 跨服务调用流程 | L4 / L5 | L3（不要拉所有服务） |
| 性能 P95 / 并发 | 独立性能层 | L3（粗略） |
| UI / 真实浏览器 | 由前端测试承担 | 任何后端层 |

---

## 3. Spring Boot 4.x 关键约束

- **Web 测试统一用 `WebTestClient`**：MockMvc 仍可用，但新接口建议 WebTestClient（Reactive / Servlet 通吃）。
- **`@SpringBootTest` 谨慎**：能用切片测试就不用全栈，否则 CI 时长爆炸。
- **`@MockitoBean` / `@MockitoSpyBean`**（Spring Boot 3.4+）替代旧 `@MockBean`。
- **Testcontainers 用 `@ServiceConnection`**：自动注入 datasource / kafka / redis 配置，禁止手写 `application-test.properties` 硬编码端口。

## 4. 用例命名与组织

```
src/test/java/<package>/
  ├─ unit/                    # *Test.java         L1
  ├─ slice/                   # *SliceTest.java    L2
  ├─ integration/             # *IT.java           L3 （Failsafe 跑）
  ├─ contract/                # *ContractIT.java   L4
  └─ smoke/                   # *SmokeTest.java    L5（部署后从外部触发）
```

命名约定（中文用例名鼓励）：
```java
@Test
void 创建订单_库存不足_应返回409并不写库() { ... }
```

打标（与 01 章追溯一致）：
```java
@Tag("REQ-2026-002-AC-03")
@Tag("api:POST /v1/orders")
@Tag("layer:L3")
```

## 5. 集成测试（L3）骨架约定

- **每个集成测试类只关心一个 bounded context**，禁止"超级集成测试"。
- 启动方式：`@SpringBootTest(webEnvironment = RANDOM_PORT)` + `@Testcontainers` + `@ServiceConnection`。
- 数据库 / 缓存 / MQ 必须用 Testcontainers，**不允许 H2 / Embedded Redis** 替代。
- 外部接口（C 类）一律走 WireMock（见 06），禁止真连三方。
- 时间敏感逻辑用 `Clock` 注入 + `MutableClock`，禁止 `Thread.sleep`。

---

## 6. 契约测试（L4）双向

| 方向 | 工具 | 触发 |
|------|------|------|
| 提供方验证（实现 ⊇ 契约） | Schemathesis（OpenAPI 模糊） | 每次 PR |
| 消费者驱动（消费方期望 ⊆ 提供方） | Pact / Spring Cloud Contract | 消费方 PR + 提供方夜间 |
| 异步契约 | Spring Cloud Contract for messaging / 自研 schema-validator | MQ 改动时 |

最小流程：
```
消费方 PR → 生成 pact 文件 → push to broker
提供方 nightly → can-i-deploy 校验 → 阻塞或放行提供方部署
```

---

## 7. E2E / 烟雾（L5）

- 用 **Karate**（建议）或 Newman：`tests/e2e/*.feature`，与代码同仓。
- 部署后第一时间运行**烟雾子集**（< 60s），失败即回滚。
- E2E 用例只验关键链路（登录、下单、支付、对账），避免成为 L3 复制品。
- 数据：通过"测试租户 / 影子账号"完成，禁止用真实用户数据。

---

## 8. 性能与混沌（独立层）

- 性能：JMeter / Gatling，独立流水线；以 `criticality=P0` 接口为基线。
- 混沌：Toxiproxy 注入超时 / 抖动；Chaos Mesh 注入 pod kill；演练月度。
- 两者**不阻塞合并**，但产出趋势报告，回归到 SLA 看板（见 07 / 08）。

---

## 9. 选型决策与替代

| 决策 | 选 | 不选 / 慎选 | 理由 |
|------|----|------------|------|
| Web 测试 | WebTestClient | MockMvc（保留） | 与 4.x 一致，Reactive 通用 |
| Mock 库 | Mockito + `@MockitoBean` | PowerMock | PowerMock 维护差 |
| 契约（提供方） | Schemathesis | Dredd | Schemathesis 模糊更强 |
| 契约（CDC） | Pact | Spring Cloud Contract（备选） | Pact 多语言广 |
| E2E | Karate | Postman/Newman（仅辅助） | Karate 表达力 + 内置断言 |
| 数据/中间件 | Testcontainers + `@ServiceConnection` | H2 / Embedded | 真实度 |
